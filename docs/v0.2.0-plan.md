# v0.2.0 implementation plan

1. Add a transport independent `Principal` and carry it from CLI/MCP authentication through service, audit, and session namespaces. Keep OAuth audience for resource routing only; use JWT subject for caller identity.
2. Introduce narrow profile, credential, approval, and audit provider interfaces. Adapt current YAML, file credentials, SQLite, and stderr implementations, then move service execution through those interfaces.
3. Split public connection metadata from resolved credentials. Resolve credentials only at the SSH execution boundary while preserving legacy YAML.
4. Add configured per-hop host key verification with strict pinning and an explicit insecure self-hosted compatibility setting. Reject changed keys with a distinct error.
5. Add runtime mode and target policy. Validate DNS answers and connect to the validated address; reject unsafe Cloud targets and tunnels, including bastion and delegated hops.
6. Preserve MCP protocol versions, routing headers, Bearer and OAuth semantics while forwarding Principal to service. Scope sessions and authorization records to the authenticated context.
7. Add targeted regression and protocol tests, run fmt/clippy/test/release build, update CI and security/architecture documentation, then bump to 0.2.0.

Keep changes within the current crate unless a concrete dependency boundary requires a workspace split. Preserve local command and YAML behavior.
